# Lean ROM plan (revision of explore-codebase-and-what-binary-nova.md)

## Current implementation order

1. **Extract Settings first.** [Three pages in one Rust package](#one-renderer-for-several-settings-pages) fit under the committed ceiling and retained parent focus and saved edits across reboot. Use one package renderer and data-defined pages. Next bind the real process owner and executable window, resolve provider grants and use one manifest builder for C and Rust. Price the complete external Settings app with dynamic editors and readable recovery. Disconnecting the resident callbacks identified a 14,036 B opportunity. Count the saving when equivalent workflows ship.
2. **Unify radio operations before extracting VFO.** Route KRX, physical input and RigWire through the same coordinator. Keep slot intent, physical receiver assignment and timestamped observations distinct. Qualify external VFO, scanner and memory manager together under PTT, foreground switches and media replacement. The [radio acceptance cases](#radio-acceptance-cases) cover hardware sharing and restoration.
3. **Move the remaining presentation out of ROM.** External Home owns menu placement, named icons, editors and ordinary widgets. Use one elapsed-time animation clock and one presenter for panel and headless output. Slightly lengthen the transition duration after measuring both modes. The SDK derives thumb extent and position from the same viewport used to draw the list, through the final row. Retain readable recovery and installation with storage unavailable. Price the shared KRX/Wire operations with both callers linked.
4. **Defer a filesystem rewrite.** The external memory manager can use bounded, revision-checked record edits independently of whole-bank import. The [publication study](#whole-bank-publication-decision) prices the additional import guarantee. Release each slice with equivalent workflows, a non-increasing full-feature image and a lower ceiling after each saving. The target is **79,999 B or less**. Even the incomplete 91,924 B diagnostic image exceeds it by 11,925 B.

Supersedes the ordering of the earlier plan, not its content. Rule added: **flash goes down**.

## Rule

- Every commit states its `./kern size` delta. A commit may grow flash only if the same stage has already banked more than it spends.
- Stage order is by bytes freed, not by feature appeal.
- Baseline: 120,264 / 120,832 B (2026-11-20, commit 9be91337b). AGENTS.md target: under 80 KB.

## Stages

Savings are estimates until measured; the bloat tool's own figure for syscall thinning (8.4 KB) is optimistic.

### S0. Size gate (0 B)
`./kern size` fails when flash exceeds the recorded baseline; `./kern bloat baseline|diff` per stage.

### S1. Property registry: one table, three consumers (est. -5 to -8 KB)
One `abi` table: `Prop { id, kind, min, max, step, cap_read, cap_write, label }` plus one firmware accessor `prop_get(id) / prop_set(id, value)`.
- Syscalls: `RfGet`, `RfSet` scalars, `RfVfo STATE/WATCH_MODE/MONITOR`, `IoPower`, `AudCtl`, `GfxCtl`, `UiStatus` scalars collapse into `PropGet` / `PropSet`.
- Settings: a page is a list of property ids; `populate_item` (624 B), `finalize_entries` (428 B) and the per-page tables go.
- RigWire: `read_sys_facet`, `handle_resource_set` (524 B), `handle_control_service` (776 B) become transport over the same accessor.
- New for apps: subscribe to a property change instead of polling `STATE`.

### S2. ABI v4 in the same break (est. -1 to -2 KB)
Packages must be rebuilt for S1 anyway, so do it once.
- Uniform `KErr` return; removes the ambiguous "0 = refused or success".
- Dispatch by `abi::OP_TABLE` function pointer; per-domain `match` trees go.
- Pointer and length validation driven by the existing `Sig` (In/Out/Str), done once in `kern_call`.

### S3. Settings out of ROM (est. -6 to -8 KB)
After S1 Settings is a generic list renderer over property ids, so it fits a KRX package. ROM keeps: launcher, VFO, and the system-action hook.
Failsafe: Recovery already runs from KernFS; if `/apps/settings.krx` is missing the launcher shows the reinstall dialog (Phase 6 of the old plan).

### S4. Table service (est. -1 KB, enables external memory management)
One accessor for every `16 + (index << N)` table (channels, contacts, zones, bands, hits, FM): `TableRead/Write/Find/Count` by `TABLE_ID_*`. Channel CRC, zone masks and `user_tag` handled once. An external memory manager needs only this plus `krx_vfo_get/set`.

### S5. Radio service into the kernel (size neutral, structural)
Coordinator is already monomorphised once, so no bytes here; do it after S1 to S4, when the property table defines its public surface. Adds the sequencer (watch, scan, sweep) as one state machine instead of flags.

### S6. Reference-firmware feature matrix
Compare `inspo/` (f4hwn, fagci, deltafw, UV-KX) against the property and table ids; every missing feature becomes a property id or a table, not new code paths.

### Deferred
Actor multitasking and the XIP install region (old Phase 2): they need the bytes S1 to S3 free, and the PY32F071 page-size question is still open.

## Already done (commits c8f1e15c2..9be91337b)
Single ABI crate with icons/caps/scopes; manifest package builder; capability check at dispatch; `RadioTx` gate and TX permission on FSK; VFO as 64 B channel record; scrollbar; headless cadence.
Cost so far: +804 B against the 119,460 B session start. S1 has to repay that first.

## Revised execution order — 2026-11-20

This section supersedes the S1–S6 ordering. Sources are the original `~/.claude/plans/explore-codebase-and-what-binary-nova.md`, its Claude session `ef4e17b8-fdeb-4f56-871e-ba1a58b58122`, the measured flash audit (§§2, 19, 32, 36, 40, 44), the archived optimization master plan (§2), and the KRX execution proposal (§4). Earlier measurements and design rationale remain above.

**Flash budget.** Last committed UV-K1 ceiling is 120,212 B. The existing working-tree ELF uses 120,252 B flash and 14,440 B static SRAM. Its named symbols attribute 9,822 B to Settings, 1,432 B to VFO, 11,347 B to syscalls, 6,320 B to RigWire and 6,602 B to GUI. Moving all named Settings and VFO bytes would explain only 11,254 B of the >40 KB reduction needed for a conservative **<80,000 B** release. Some shared code will remain. Treat module sizes as places to investigate and compare whole linked images after each extraction.

1. **Establish the feature and size baseline.** Use the committed profile, toolchain and packages as the comparison point. Inventory public operations, sub-ops, manifest actions, stock workflows and recovery with storage unavailable. Review the interrupted diff independently. It renumbers calls while reporting ABI 3.0, and swaps app overrides into the preference buffers during flush. Neither design should become the reference contract. Preserve callable behavior in a service or an equivalent tested SDK operation before retiring any entry. Record resident flash, external package bytes, SRAM/stack high-water and navigation latency separately. Fix the ceiling comparison for explicit selection of the same target/profile.

2. **Make Settings the first extraction and Rust KRX the first proof.** A tiny Rust display/preferences package and a C fixture run through the same loader, entry convention, manifest, linker-map checks and packer. Use `no_std`, no heap, static calls through the ABI. Exercise read-only data, mutable state, callbacks, relaunch, code-window limits and panic cleanup. For movable images test at two load addresses. If LLVM cannot satisfy the current flat PIC profile, validate the fixed-map native profile in the execution proposal. Measure equivalent packages before selecting the default. Version the ABI once, reject incompatible images at admission, generate C/Rust/host bindings from shared declarations. Keep target-side metadata limited to fields the firmware consumes.
   - **Preferences** are the user's durable choices. Only an explicit authorized preference edit updates the canonical CRC-protected domain and queues a save. **Controls** belong to a service and a caller. Apply them to live device state. Owner exit, preemption or fault recomputes the effective setting from surviving owners and the current preference. Telemetry is read-only. Test a preference change and flush under an override, including equal values, two callers and a power cycle. Enforce the same ownership policy for RigWire and file writes, replace, remove and rename.
   - Move Settings pages, labels, choices and app-specific editors to the package. The catalog resolves a declared Settings role and enumerates actions by scope. Presentations choose their menu placement and named icons. Apply readable boot/recovery defaults even with missing media, corrupt prefs or a missing Settings provider. Preserve intentional dim/off choices in normal operation and provide a readable recovery path.
   - Index assets on mount/install/change and page through a bounded cache. A splash preference identifies a catalog asset with stable identity across reorder. Transition and duration are independent options. The existing 0–3 field selects the transition, while the image already comes from a path. Today the picker calls `list_dir` on open and defaults to a numbered filename. Define deterministic deletion/rename behavior, a text fallback, and the same lookup for jingles and rogers. Test with a library larger than the RAM cache.

3. **Give radio state one writer.** Move policy and state transitions into a host-testable coordinator in `kernel::service::radio`. Firmware supplies clocks, power/calibration inputs and statically bound RF/audio facets. Resident PTT, KRX and authenticated RigWire submit the same slot-addressed commands with distinct owner identities and receive the same result. Hide mutable channels. Today RigWire tuning writes hardware for the requested slot even when it is inactive, and its modulation/squelch path edits the active channel. Apply a validated command atomically and retune only the resource currently assigned to that slot.
   - Publish a coherent snapshot with revision, active/listening/TX slots, memory identity, measured signal, watch/monitor state, lease owner, TX permission/reason, timer and audio route. Deliver events for transitions, tone/digit/frame/scan hits and preemption. Coalesce meters, preserve ordering for control events, signal overflow and resync from the snapshot. Reuse the existing arbitrator and event bus. On client failure release only its resources. Verify local PTT preemption, remote disconnect during TX and an unrelated process exiting while another owns TX.
   - Route all keying through one decision on effective TX frequency, current bandplan, capability, channel inhibit, BCLO, timeout, battery and thermal policy. Share the gate across PTT, tones and packet modes. Describe RX ranges, tuning steps, bandwidths, modulation and available paths per physical receiver. Supply bounded timed visits for watch, scan, sweep and tone search with priority, dwell, settle, skip, hold/resume and cancellation. Keep protocol decoding, scan strategy, waterfall drawing and history in packages wherever timing permits.

4. **Make memories an actual storage service.** Put typed table descriptors and record codecs behind one bounded KernFS reader/writer for channels, zones/lists, contacts, bandplans, hits and FM presets. Provide enumeration, paged reads, insert/update/delete, stable record identity, conflict detection and change events. External packages handle filtering, editing, reorder, bank selection, import/export and batch programming. Define interrupted-batch recovery and dangling-reference behavior for a channel in a zone, priority list or active VFO. RigWire and the on-device manager use identical validation.
   - Separate the full stored record from its live RF projection. `GET_CHANNEL` currently starts with an empty record and reconstructs operating fields, losing name, UID, zones and opaque metadata. Merge edits against the original record. Resolve the actual 8-byte extension versus the specified 16 bytes with a versioned layout, byte fixtures and an explicit conversion preserving legacy fields. Keep logical shift-based indexing. A 16-byte header plus 64-byte records crosses a 256-byte page at record 3. Test cross-page writes and power loss on the implemented KernFS geometry.
   - Persist the last user VFO session on idle or orderly shutdown. Include A/B/C, memory/free mode, active slot and watch policy in a versioned consistent checkpoint. Temporary scan visits and app previews never become the boot frequency. Verify edit → recall → tune → power cycle with all three slots.

5. **Ship and exercise a completely external VFO.** Select it via a manifest role. It must support frequency entry/step, RX/TX split and reverse, A/B/C and priority watch, memory recall/store, monitor, signal meters, modulation/bandwidth, tones, calibrated power, VOX/PTT, scanning and status through the public SDK. Combine it with the external memory manager and a background scanner or packet listener. Test switching, focus, resumption, physical PTT and foreground loss. Use bounded foreground/background state and measure the worst case before expanding process count. Use one elapsed-time animation clock for panel and headless modes, and derive scrollbar extent/position from the visible window and content offset. Verify first/last page, dynamic lists and sub-30 ms input response.

**Reference acceptance.** Maintain one row per user-visible behavior with reference checkout and source/menu entry, hardware dependency, Kern service/package, test and result. Seed with the following independently inspectable cases. Inventory the remaining firmware forks, plugins and CHIRP options in `inspo/`; distinguish unique functions, duplicates, hardware-limited functions and non-firmware tools. A declared capability alone never closes a row.

- F4HWN — A/B plus two priority channels and complete switchable configuration banks (`inspo/f4hwn/README.md`). Falcon adds four priorities, multilist watch, range scan, blacklist/history, waterfall zoom and 1K/4K CHIRP profiles (`inspo/Falcon-firmware-UV-K1-K5v3/README.md`). Test scan scheduling while editing inactive memories and restoring a bank.
- Fagci — multichannel scan, analyser, frequency counter and squelch viewer (`inspo/fagci-k1-fw/src/helper/scan.c`, `src/apps/` within that checkout). DeltaFW — scan groups, spectrum/waterfall and AirCopy (`inspo/deltafw/src/apps/`). Test bounded sample streams, cancellation, return to the voice VFO and transfer integrity.
- UV-KX and GoguFW — DTMF, FSK messenger, heard log, range check and named broadcast FM memories (`inspo/UV-KX-firmware/src/app/`, `inspo/gogufw/README.md`). Include tone/code search, PTT-ID, repeater access, FM audio routing and packet reception during watch. Exercise optional SSB/raw RX, CW, digital messaging and sensor decoding against the rQuansheng, CW/SECMSG and temp433 references on supported hardware.

**Flash exit criteria.** After Settings, compare linked images again. After external VFO and memory management, remove the superseded resident UI and adapters. If the gap remains, measure shared RigWire/ABI codecs, duplicate list/modal renderers and app-only graphics moved with their consumers, then loader/boot/recovery duplication in that order. Keep the resident readable recovery screen, core RF safeguards and update path functional with storage unmounted. No projected saving counts toward the target. Accept a slice on a net release-flash reduction (host/package-only work may be neutral), zero warnings, ABI/package rebuilds and passing behavior tests. Final acceptance requires <80,000 B resident, a measured stack margin under concurrent load, hardware RF/timing checks and a tested disposition for every reference feature. Defer internal-flash XIP until measured latency warrants it.

This measures transitively linked code and data. Replacement UI/services and real package admission must be included in the shipping comparison. Even the stripped experiment needs another 24,513 B for <80,000 B.

The equivalent C fixture produced 84 B (212 B packaged). Both used the existing linker script and KRX packer. - First extraction deliverable: a Rust KRX Display page with real preference read/write, transient preview and catalog discovery. Qualify that page and its lifecycle first, then port the remaining pages before removing the ROM entry.

### Decisions after the launcher test and reference audit

**Rust is viable on the existing launcher.** A 292 B Rust N1 package (164 B payload) ran on the UV-K5 V3 QEMU model with the UV-K1 working-tree release ELF (SHA-256 prefix `c0d203ca781ca24c`). A host fixture formatted a private 2 MiB NOR image with this checkout's KernFS, wrote `/apps/probe.krx`, remounted it and compared the bytes. Keypad 3, EXIT, 3 produced UART markers `[start][contrast=50][exit][start][contrast=50]`. Each START read the real Display preference and each RENDER checked the package's writable static. This exercises discovery, admission, the trampoline, syscalls and relaunch. Use this sequence as the SDK integration test for both compiler backends. Preview arbitration, fault cleanup and physical-device timing still need their own tests.

**Budget the larger cut now.** Starting with the 104,512 B callback-disconnection build above, disconnecting only `runtime::syscall::ui::draw_widget` gave 101,492 B (−3,020). Also disconnecting only `wire::handle_control_service` gave 98,320 B (−3,172 more). Wire framing, file transfer and event handlers remained linked. Both experiments used the same release flags. Removed call sites produced unused-code warnings. Even this incomplete image needs **18,321 B** more to reach 79,999 B. The full 6,316 B Wire module therefore cannot be budgeted as duplicate controls. Put equivalent widgets in the SDK and make Wire adapt the same typed commands used by KRX. Measure again with every operation callable.

Before investing in a resident widget library or adding loader profiles, price the **external system shell** as a whole. Move launcher presentation, ordinary dialogs, keyboard editors, shortcut picker, app artwork and list rendering to packages. Retain resident focus and input routing, lock enforcement, RF deadlines, framebuffer presentation, a small readable recovery view and the update path. A shell handoff carries the launcher's selected item and viewport by stable identity. The process manager owns the active package window. Compare the same start → launch → exit → return workflow with the shell installed and with storage unavailable. Count the loader, fonts, SDK calls, recovery view and switch latency in that result. The <80,000 B target remains open until a feature-complete release reaches it.

**Contracts that change the order of implementation**

1. **Bound the executable window before porting a whole app.** `data/arena.rs` partitions 4,096 B of code and 2,048 B of scratch. Admission, memory-region queries and overlay placement use the full 6,144 B in several paths. Launcher entries also borrow the arena base. Derive admission, layout, region queries and the packer limits from one layout per profile. Publish separate code, writable data, overlay and stack requirements. Keep launcher focus outside reusable bytes. Exercise a full-window package while uploading a file and refreshing the catalog, including suspend and relaunch. Prove the declared stack margin under IRQ load.
2. **Use one catalog for install, launch and settings actions.** The current directory pass sees eight entries and the action cache holds sixteen. Shortcuts persist a 15-bit path hash and select the first match. Use a versioned index with bounded page reads, durable package/action identities and an explicit choice of default provider per role. A package declares what its action does and a named icon. The shell chooses placement. Catalog publication follows successful install, replace or removal. Test a ninth package, unrelated files preceding packages, duplicate titles, renamed files and provider removal. Remote launch must invoke the same operation as keypad launch. Today's `ACTION_APP_LAUNCH` only validates the index.
3. **Make RF time and identity part of the service contract.** The main loop computes elapsed time but discards it for radio. The coordinator advances timeout, lead-in and dwell by one nominal 10 ms tick per call. Use wrap-safe monotonic deadlines for TX cutoff, lease expiry and watch visits. Reconcile against the current hardware observation after a late wake. Validate with jitter, a stalled foreground, sleep/wake and clock wrap. Enumerate the actual VFO slots once. The kernel enum includes D, the coordinator stores three channels, several accessors clamp D onto C, and pair-watch maps C to D. Validate a complete slot-addressed command before applying any field. Cover switching from triple watch on C to pair/priority mode and editing during TX. Carry a revision through snapshot and event delivery. The current bus codec omits RF masks, truncates owner IDs and cannot decode the lock events it emits. Clients must be able to recover the full current owner, resource and slot after overflow or reconnect.
4. **Prove full-size banks and atomic publication before building the editor.** Falcon 4K stores 4,096 channels. A single ORDS file needs `16 + 4096 × 64 = 262,160 B`. KernFS and both Wire peers cap files at 262,144 B, sufficient for 4,095 complete records. Keep one ordinary channel file and extend generic file addressing. Prototype the existing inode's unused `root_page` for an index root on large files. Include GC, mount, free-space accounting and boot/update readers in the comparison. Derive the negotiated transfer limit from the supported geometry. The current extents reply writes an 8 B prefix and eight 2 B roots while checking and reporting 20 B. Generate the versioned descriptor size from its encoding.
   - Give KernFS a staged writer that publishes the replacement through one destination inode commit after length and integrity checks. Today Wire truncates an existing destination at open and deletes it on a failed close checksum. KernFS rename also removes an existing destination before committing the new name. Preserve the previous generation until publication and reclaim staged pages on interruption. Exercise last-record edits, remount, nearly full media, concurrent readers and interrupted CHIRP import. Keep checksums and cleanup outside the input dispatch loop in bounded increments.
5. **Share frame time and viewport geometry.** External `GfxCommit` calls the panel driver directly while the resident renderer observes headless mode. Route both through one presenter with dirty regions and panel/remote consumers. The UI tick already has elapsed time, but enqueues a unit `Event::Tick`. Animate from elapsed time so delayed frames and refresh rate changes preserve duration. For large lists nearest-pixel rounding can place the thumb at the endpoint before the last item. Reserve the endpoint for the true maximum offset where the track has travel, handle a sub-four-pixel track, and derive content, visible extent and offset from the same clipped layout. Verify 4,096 rows, partial rows, list shrink during animation, and identical panel/remote frames at equal timestamps.

### External launcher, recovery and input latency

A disposable release build from `7c25aa322` replaced the built-in launcher with a catalog dispatcher and two-line fallback. Settings, VFO, the normal compositor, RF services, Wire and the KRX loader stayed enabled. Two Rust fixtures used the existing N1 profile. The 552 B Home package enumerated two declared actions. The 312 B child displayed a detail view. The resident dispatcher selected Home from a fixture manifest scope, saved the selected action outside the executable window and deferred replacement until the guest callback returned. The fixtures used unique action IDs. Production references need the package identity as well.

- **Footprint.** Stock and prototype measured 120,208 → 117,700 B resident flash and 14,432 → 14,380 B static SRAM. The 2,508 B flash difference includes the dispatcher, fallback and catalog query. It covers the navigation fixture. Stock launcher artwork, grid/list options, shortcuts and animation still need package implementations and size measurements. The prototype build flagged one obsolete launcher helper.
- **Lifecycle.** On UV-K5 V3 QEMU, DOWN selected Memories, MENU started the child, and EXIT restored Memories. The full 1,024 B panel image after EXIT matched the pre-launch selection. UART confirmed Home exit, child start, child exit and Home resume in order. On a formatted volume with no packages, the fallback displayed install/retry instructions. Through a private emulated UART the stock RigWire client installed both packages, verified their CRCs, and MENU opened Home on the same boot. With erased SPI, the existing early-boot UI showed Invalid Storage and EXIT halted before RigWire started. Provide a readable, nondestructive recovery/update route at the mount-failure stage as well.
- **Timing.** Measured QMP key press to first matching LCD content frame, excluding the status bar, over one selection and four open/back cycles. With the default key tone, nine samples took 53.5–61.9 ms (median 56.8). With the same firmware and the key beep disabled in the CRC-sealed audio preference, they took 8.3–10.5 ms (median 10.2). Default feedback synchronously plays a 40 ms note during event dispatch. The driver also waits for cold amplifier startup and route restoration. Give local sounds a bounded, deadline-driven player under the coordinator's audio arbitration. Reuse the boot melody note stepping. Preserve audible feedback and verify key-to-frame latency with the tone enabled, including physical PTT preemption and carrier return. Hardware timing remains a release gate.
- **Remaining budget.** Adding the previously measured Settings/VFO callback, widget and Wire-control disconnections to this shell build gave 95,684 B. Also disconnecting the ordinary text editor, option-sheet event/render paths and shortcut-drawer rendering gave 91,924 B. Resident popup, lock handling and boot dialogs remained. These incomplete diagnostic images leave at least 11,925 B to find before restoring displaced behavior and measuring again. The remaining ELF attributes 10,727 B to syscall dispatch and 3,586 B to Wire handlers, chiefly file transfer. Prioritize shared RF command execution and staged file operations; measure them with both callers active.

**First prerequisite for caller-owned controls.** The loader currently constructs a PID from the dynamic application index and discards the PID returned by the process table. On this configuration the index is 3, which the table assigns to Power during boot. RF locks, service exports, IPC and tray cleanup use the slot PID. Reserve the process record before installing a provider, bind its allocated owner to the execution slot, release it on load failure and retire it after EXIT. Keep the durable package/action identity for navigation. A reused SRAM address or application index must never inherit a previous instance's controls. Add a host test for app → child → app covering distinct owners, failure rollback and an unrelated radio lease surviving both exits.

### Memory recall and lossless editing

**Reproduced on `f24e6bb1c`.** A host test loaded a production 64 B record through `load_channel_into_vfo`, stepped a simplex channel by 12,500 Hz using the coordinator and exported via the same empty-record serializer as KRX `GET_CHANNEL`. Besides RX and its checksum, **34 payload bytes changed**. The 16-byte name, UID, zone membership and unknown extension were lost. Requested power went from 1,750 to 2,000 mW and bandwidth from 15,750 to 12,500 Hz. The stock firmware header writer also emits `NAHC` on little-endian targets. The stock host mount rejects it and accepts literal `CHAN`.

1. **Fix edit semantics before changing the disk format.** Keep exact requested tuning in the slot. Derive the supported hardware settings at apply time and expose effective readings separately. An external editor patches the original memory using an expected revision and the fields the user edited. Memory recall, tuning, reverse, talkaround and scan visits do not write the bank. Explicit Save updates the selected UID. Duplicate allocates a new UID and copies the full record. If the bank changed while an editor was open, resolve the UID against its generation and report a conflict on a changed or deleted target. Preserve free-VFO state when the referenced memory disappears. Test simplex, relative repeater offset, fixed split and TX inhibit separately when editing RX.
2. **Keep the format and migration code with its consumers.** A C or Rust memory package and the host importer need a shared byte specification and golden files. The resident coordinator needs RF requests, identity and revisions. Stage edits through generic file operations. Supply a documented codec for legacy native-endian and literal-ASCII headers, validating version, capacity, length and checksums before conversion. Preserve legacy eight-byte extensions verbatim inside a reserved `LGCY` envelope until their owner converts them. Use literal FourCC bytes for new tags. Resolve the legacy `tx_limit` unit by producer/version before applying it. The spec calls it deviation and the coordinator treats it as a timeout in 15-second units.
3. **Use one publication for the bank.** The proposed v2 base totals 64 B: 29 B of existing RF/identity/protocol fields, one status byte, 16 B name, 16 B app extension and 2 B CRC. The status byte records occupancy and presence of audio detail. Nine existing audio bytes, five reserved bytes and a CRC fit one 16 B detail record addressed by the same slot after the base array. Omit trailing unused details. Keep holes and unassigned UIDs distinct, clear detail presence when reusing a slot, and migrate ambiguous legacy slots with their bytes intact for review. A 4,096-slot bank spans 262,160–327,696 B. Editing one slot stages its changed pages and publishes one inode generation. Measure near-full media and interrupted writes before adopting the layout.
   - An alternative sharing immutable profiles used 262,176 B with one profile, 262,224 B with four and 327,696 B with 4,096 distinct profiles. These are external storage bytes. Prefer slot addressing for its bounded reads and independent edits. It needs one 64 B base and one 16 B detail buffer per streamed record. Include stack and filesystem buffers in board measurements. Keep each VFO snapshot self-contained across bank replacement. A proposed v2 snapshot uses the 32 B header, two bases and up to two positional details (160–192 B). Version that change explicitly and retain import of the fixed-size v1 snapshot.
   - Keep the specified base offset `16 + (slot << 6)`. Slot 3 begins at byte 208 and crosses the 256 B logical page boundary. Slot 63 crosses the 4 KiB logical boundary. Account for both pages in I/O and staged writes. Physical placement belongs to KernFS.
4. **Verify host interoperability independently.** Falcon 4K's CHIRP driver stores frequencies, labels and attributes in separate regions and interprets the last 30 memories as band ranges. Import those as ranges and preserve scan-list membership, direct/inverted cross tones, skip and explicit deletion. A CSV edit overlays the columns it represents on a matching native record. Keep CSV comments separate from app extensions and preserve new or unrepresentable fields in native backups. Identify source/target representations explicitly on export. The tree has a binary mount validator and reference drivers. The Kern CSV adapter still needs implementation and CHIRP integration tests.

**Prototype result.** The current coordinator ran on a mock RF device. Its resulting RX value fed a disposable field-edit codec. Import/export through the production mount validator and its in-memory backend retained the complete binary fixture apart from RX and recalculated CRCs. A separate 4,096-slot codec test round-tripped every legacy record byte, repeated a targeted edit at every slot, preserved a native twelve-byte unknown payload and rejected corrupt base/detail CRCs. These tests cover the codec, coordinator and host validation. Device transfer, concurrency, power interruption, CHIRP and release flash remain implementation gates. This experiment earns no resident flash credit.

### Full bank, atomic edits and resident cost

**A record write currently has two publication points.** On an emulated NOR device, the stock writer updated slot 3 at byte 208. Six injected power cuts recovered the first 48 edited bytes and the last 16 original bytes. Each page had a valid filesystem CRC. Use one inode commit for all pages in an editor operation, including discontiguous base, detail and count changes. Check the expected file revision before staging. Run reclamation before the write, publish the new roots together, then retire superseded pages.

**Storage geometry.** A disposable KFS3 layout reused the eight inode bytes assigned to `record_shift`, `owner_pkg`, `root_page` and `type_fourcc`. Stock code only initializes those fields. This gives twelve roots and a 24 B inline payload in the same 64 B inode, retains names and permissions, and addresses 393,216 B per file using the existing index depth. The 327,696 B bank occupied eleven roots. Both SRAM flasher packages rebuilt with the revised 32 B extents descriptor, and a host test walked the raw extents and compared every byte. Actual firmware update/recovery, old-volume migration and external producers' use of the reserved bytes still need verification. Version the descriptor with the volume geometry.

**Measured UV-K1 release comparison against `453eb6aac`.** Stock used 120,208 B resident flash. Widening the inode and both Wire limits used 120,200 B. Adding an independent atomic writer overflowed the linker region. Sharing one copy-on-write loop between edits and ordinary writes and moving reclamation out of individual page allocations used **120,168 B**. All linked variants used 14,432 B static SRAM. Adding a callable, bounded multi-range KRX adapter brought the image to **120,512 B**, 304 B above stock. Price the final shared Wire/KRX service with both callers reachable. The 40 B core saving alone cannot fund that adapter.

**External workflow.** On UV-K5 V3 QEMU the production RigWire client with the revised limit uploaded and downloaded the entire bank byte-for-byte. In a separate run, the normal launcher started a 314 B Rust KRX fixture. It submitted two prepared edits to the last slot. After restarting QEMU on the same SPI image, RigWire returned the expected complete bank. NOR fault injection across the three affected pages produced only the old or new bank with an unrelated file intact, both on fresh media and with at most 30 free pages before remount. These tests cover bounded edits. Whole-bank replacement, stale concurrent editors, faults within a NOR program or erase, and physical-radio timing remain open.

**Next storage decision.** Prototype a private upload root for the destination inode. Page tags identify their owner by inode number, so transplanting a temporary file's root alone breaks GC ownership. Let reclamation trace the published and in-progress roots during streaming. Verify length and checksum before the single destination commit, and reclaim abandoned pages after reset. Coalesce transport chunks in the existing 512 B staging buffer. On the same freshly formatted NOR model, full-bank writes in 256 B groups required 10,462 program operations, versus 8,499 in 512 B groups, both with zero post-format erases. Verify interruption, available-space accounting, retry and latency with other services active before committing to a new disk format.

### External Display page

**Two distinct failures in the interrupted preference changes.** The default launcher rejects an external Settings package declaring `Preferences` because `SysContext::caps` omits that service. In a disposable build that advertised it, a six-row Rust KRX previewed contrast from 50% to 60%. Save and flush both returned success. Reboot restored 50%. The setter compared the requested value with the live preview, cleared the override and skipped marking the durable value dirty.

**Service contract.** Publish available services from the enabled board configuration. At admission resolve the package's requested rights against its grants. The package declares a configuration action, and Settings chooses its position and icon. Keep canonical preference bytes available for reads and persistence at all times. Store bounded live requests separately with their process owners. Only controls explicitly supported by the display or audio service can affect hardware. Recompute effective output on preview, preference change and owner exit. Report Save success after the domain write completes and preserve dirty state on failure.

**Tested through Settings on QEMU.** A default-profile UV-K1 build on the UV-K5 V3 model discovered a 1,190 B Rust package through its catalog declaration. With the resident Display page removed, MENU opened the package, EXIT returned, and MENU reopened it. Saving the preview restored 60% after reboot. Exiting without saving restored 50% immediately and after reboot. Both 48 B preference files had valid CRCs and identical bytes outside contrast and CRC. A host test exercised two overlapping owners, release order, a full control table and rejected a splash option submitted as a live control.

**Linked cost.** Advertising the service alone used 120,248 B. Resolving nine hardware fields individually used 120,668 B. Applying the same four owner records in one pass per domain used 120,500 B. Replacing the resident Display page and linking its catalog route reduced this to **120,320 B**, with 14,440 B static SRAM and zero warnings. The prototype used a fixture role and existing slot PID. Production still needs assigned process identities, provider grants, dynamic root icons, optional grayscale and a stack measurement. Reuse the external renderer for additional declarative pages before lowering the 120,212 B ceiling. Shipping savings remain uncredited.

### One renderer for several Settings pages

**Normal menu path.** A disposable 1,822 B Rust package (1,642 B executable payload) supplied Display, Buttons → Tweaks and Battery → Tweaks. Each existing menu row invoked a different action in the same package. The catalog previously retained individual action IDs for apps but only combined scope bits for modules. Index module actions individually and let the calling UI choose placement. Use package identity plus local action identity and a selected provider for each service. The fixture used three unique action IDs.

**Verified on QEMU.** Keypad edits saved contrast at 60%, hold delay at 500 ms and signed battery trim at −10 mV. After reboot, all nine checked domain files across the three runs had valid CRCs. Only the selected field and its CRC changed. EXIT restored each parent menu's content pixels, and MENU reopened the same page. Across those workflows, 760 B of the 1,940 B linker stack region retained its paint after return. This measures those interactions after boot's final stack repaint. Physical interrupt load and concurrent radio/transfer activity still require measurement.

**Resident footprint.** Sharing the renderer and removing the superseded native descriptors and signed range editor used **120,188 B flash**, 24 B below the committed ceiling, with 14,440 B static SRAM and zero warnings. A fresh export of committed `32a141660` linked at 120,208 B flash and 14,432 B static SRAM. The prototype saves 20 B of flash and adds 8 B of static SRAM against that baseline. The interrupted working tree linked at 120,252 B. The isolated workspace ran 319 passing host tests. These figures still use the fixture owner, grants and signed preference adapter. The next release comparison must include their production replacements.

**Schema scope.** Exporting the compiler-selected Settings tables and round-tripping titles, row kinds, operands, choices and bounds produced 1,840 B for 66 rows across 15 default-profile pages. Enabling grayscale, passcode and the optional Info, Calibration and Debug pages gave 2,185 B for 85 rows across 19 pages. These are external metadata bytes. The shortcut binder, installed-package preferences, asset picker and privileged actions require their own behavior. Keep the page data package-local and give public service operations stable identifiers across feature combinations. The System page's local index changes from 6 to 7 in the optional build.

**Generate choices from service values.** The default UI and property registry disagree on the available choices for Key Beep, Deep Sleep, Power Profile and Startup App. The first two hold-delay labels advertise 250/350 ms while the key scanner uses 300/400 ms. All four repeat-rate labels also disagree with the applied timings. Derive labels, accepted values and hardware timing from one declaration. Preserve an existing unrepresented choice through an unrelated edit. Treat a custom startup provider as a catalog reference. Verify the applied timing or selected provider in addition to the stored byte.

### Radio acceptance cases

- **Sweep while listening.** KRX `RfBulk::SWEEP` synchronously retunes the BK4829 up to 128 times and returns on the last bin. The separate FastScan engine attempts settling, but the driver's `wait_pll_lock` returns success even on timeout. Give the coordinator one bounded tune, settle, sample and restore operation. Identify each observation by receiver, frequency, revision, sample time and validity. A package can draw a waterfall or run tone search from these observations. Test cancellation, settle timeout, a user tuning during a sweep and local PTT at each phase. On release, apply the latest user slot and route. Fagci's `src/helper/scan.c` separates tune/check/listen phases. Falcon's `sources/runtime/App/app/spectrum.c` restores the foreground after multilist watch.
- **Listen on independent receivers.** `RfResourceMask` allocates bit 6 to both secondary RX and broadcast FM. The arbiter holds one active lock, and logical VFO A/B can share one physical synthesizer. Derive conflicts from BSP-declared tuner, antenna, modem and speaker paths. Grant independent acquisitions together and arbitrate actual shared paths by owner and deadline. On a one-tuner board, verify time-sliced watch. On a two-tuner fixture, verify that background reception continues while the speaker switches, and a voice interruption restores the user's FM station and audio route. Hardware references are Fagci's `src/radio_switch.c` and UV-KX's `src/radio/functions.c`.
- **Capture, recall, save.** From an external history list, preview a hit with its recorded modulation and bandwidth, then explicitly promote it to VFO or save to memory. Restore list focus and leave the bank byte-identical after preview/cancel. On Save check the selected UID and generation, preserve unknown fields and surface conflicts. Run against Falcon's History workflow, then compare the complete bank through RigWire after reboot.

### Whole-bank publication decision

**Preserve the staging inode's identity.** A disposable KernFS writer streamed a 327,696 B bank into a private inode, checked destination revision, length and stored CRC, then published its name in one metadata commit. Recovery selected the published generation and retired the abandoned one. Separating data allocation from frequently rewritten indexes allowed four full banks plus one staged replacement. On fresh space the replacement took 6,596 programs to stage, six to publish and three to retire. All 22 KernFS host tests passed, including interrupted writes and retries. Four-bank mount took 8,772 reads (176,624 B). Time mount on hardware, interrupt live GC erases, and define how open readers retain a generation before adopting the format.

**Comparison with the specified LittleFS backend.** Fagci's LittleFS 2.11 used 15,374 B linked ARM code/constants for the measured API and 1,012 B of state and buffers before adapter and stack. On the same bank it staged in 1,285 programs and 81 erases, renamed in one program and recovered the old or new bank across 2,734 simulated cuts. Editing slot zero required 1,543 programs and 98 erases with this layout. These counts justify comparing both backends with stock features, migration and recovery enabled before changing the storage specification.

**Integration and budget.** With all default UV-K1 release features, the KernFS prototype with callable KRX editing and Wire publication linked at **121,828 B flash, 14,444 B static SRAM**. That exceeds the physical region by 996 B and the committed ceiling by 1,616 B. On a UART-only QEMU build, the host read the old bank CRC during staging, aborted and retried, rejected short and wrong-CRC closes, then downloaded the exact 327,696 B replacement. Stock firmware requires a reason byte that the host omits. The fixture accepted both encodings. Reconnecting mid-upload still returned `Busy`. Bind the writer to the transport session generation, retire it on disconnect/replacement/expiry, and budget verification and cleanup per event-loop turn. Fund this work from a measured extraction. Shipping flash saved by this study is **0 B**.
